# Mongolian help coverage and translation sources

Evidence collected on 2026-11-18. This is a coverage and provenance record, not a native-speaker approval of translations.

## Manual coverage

The English manual contains **27 topics and 40,416 whitespace-delimited words**. No `*.mn-Cyrl.md` or `*.mn-Mong.md` articles are present. Both editions require full translation and review: **54 articles remain untranslated**. Short menu labels from an upstream UI catalog do not translate the manual.

Every topic below needs both editions:

`agent-mode`, `ai-models`, `ai-panel`, `cli`, `diagram`, `docs`, `epub`, `file-ops`, `fonts`, `getting-started`, `google-drive`, `home-screen`, `html`, `install`, `markdown`, `mcp-servers`, `mcp`, `pdf-tools`, `pdf`, `projects`, `settings-integrations`, `sheets`, `shortcuts`, `skills`, `slides`, `subscription`, `tabs-and-windows`.

The application explicitly identifies an untranslated help topic and displays the English manual with `lang="en"`, `dir="ltr"` and horizontal text. This fallback is not counted as Mongolian localization. The strict `check:help-langs` command continues to fail on the missing editions; existing 22 editions still pass.

`mn-Cyrl` identifies Mongolian Cyrillic. `mn-Mong` identifies Mongol bichig, contextually **Mongolian Traditional Script**; the requested Cyrillic and Korean labels are **Монгол бичиг** and **몽곫문자**. Traditional orthography must not be generated by mechanical Cyrillic letter substitution.

## Public sources investigated

These findings identify reusable source material. They do not assert that all source rows were imported into TodOffice or reviewed by a native speaker. Product UI coverage must be measured against the actual application keys and meanings, independently of source catalog size.

### AOSP: Mongolian Cyrillic UI

- Repository: `aosp-mirror/platform_frameworks_base`.
- Pinned revision: `1cdfff555f4a21f71ccc978290e2e212e2f8b168`.
- [Mongolian resource XML](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/core/res/res/values-mn/strings.xml): 2,293 `<string>` rows.
- [Paired English resource XML](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/core/res/res/values/strings.xml): 2,315 `<string>` rows.
- Both file headers grant Apache-2.0 and identify Copyright 2006, The Android Open Source Project.

Examples verified by the same resource key:

| English value | Mongolian value | Resource key |
| ------------- | --------------- | ------------ |
| Copy          | Хуулах          | `copy`       |
| Cut           | Таслах          | `cut`        |
| Paste         | Буулгах         | `paste`      |
| Select all    | Бүгдийг сонгох  | `selectAll`  |
| Cancel        | Цуцлах          | `cancel`     |
| Delete        | Устгах          | `delete`     |
| Search        | Хайх            | `search_go`  |

Decode Android resource quoting and escapes before matching. Match the English **value**, not the resource key: AOSP's `yes` and `no` resources contain “OK” and “Cancel”. Reject unsupported markup, plural logic and placeholder mismatches rather than guessing a desktop equivalent.

### Chimee iOS: three additional contextual actions

- Repository: `suragch/Chimee-iOS`.
- Pinned revision: `af0a50531cbbe851d3a1e516b74eefd0b58a0009`.
- [MIT license](https://github.com/suragch/Chimee-iOS/blob/af0a50531cbbe851d3a1e516b74eefd0b58a0009/LICENSE), Copyright (c) 2016 suragch.
- [Copy menu](https://github.com/suragch/Chimee-iOS/blob/af0a50531cbbe851d3a1e516b74eefd0b58a0009/Chimee/CopyMenuViewController.swift): the three menu positions call `copyText`, `pasteText` and `clearText`, respectively. Copy and Paste repeat the Mongol Library values; Clear is `ᠠᠷᠢᠯᠭᠠᠬᠤ`.
- [History screen](https://github.com/suragch/Chimee-iOS/blob/af0a50531cbbe851d3a1e516b74eefd0b58a0009/Chimee/HistoryViewController.swift): `deleteAllButtonTapped` uses `ᠤᠰᠠᠳᠬᠠᠬᠤ` for the action that deletes the history and `ᠪᠤᠯᠢ` for its dismissing button. These provide contextual Delete and Cancel candidates.

The two MIT projects therefore establish **seven distinct short English action contexts**, not seven reviewed translations for every use of those English words. Reuse must preserve the relevant source license and attribution, and check each action's meaning in its new location.

### LibreOffice: larger Cyrillic corpus, separate MPL obligations

- Repository: `LibreOffice/translations`.
- Pinned revision: `9c82ddccb523e20fda8d5a855260f97d535bdeb3`.
- [Mongolian cui/messages PO file](https://github.com/LibreOffice/translations/blob/9c82ddccb523e20fda8d5a855260f97d535bdeb3/source/mn/cui/messages.po): 898,270 bytes at retrieval; its header identifies language `mn`.
- The official [component API](https://translations.documentfoundation.org/api/components/libo_ui-master/cuimessages/) reports `license: MPL-2.0`, `effective_license: MPL-2.0`, `inherit_license: true`, and links to the [MPL-2.0 license](https://spdx.org/licenses/MPL-2.0.html). This is translation-component metadata, rather than an assumption based only on the office suite's license.

Examples include “All” → `Бүх`, “User-defined” → `Хэрэглэгч-тодорхойлсон`, and “Number” → `Аравтын тоо` in a numbering-format context. The last example illustrates why context matters: a translation for a decimal numbering format must not automatically replace every occurrence of the English word “Number”. This investigation did not import the PO file. Any later reuse needs a separately identified derived catalog and compliance with its source and licensing requirements.

## Translation and review work still required

1. Map each UI key to a source translation with the same meaning, placeholders, accelerator and action context. Count mapped keys against all required application occurrences; do not equate dictionary size with UI coverage.
2. Have a competent Mongolian reviewer establish office terminology, especially traditional-script technical words and grammatical inflections. Open-source provenance alone does not establish linguistic accuracy.
3. Translate all 27 manual topics into each script while retaining headings, table rows, steps, code blocks, paths, image targets and `help://` destinations. Keep proper nouns and executable syntax intact.
4. Review traditional spelling, word boundaries, suffix separators and shaping controls in the actual vertical UI and document editor. Script-presence validation cannot assess these.
5. Pass the strict manual coverage checker after complete articles exist, then perform separate native-speaker and rendered-interface reviews. No native-speaker approval, full manual localization, application build or runtime validation is claimed by this document.

## Mechanical checks

The help checker now requires actual Cyrillic letters for `mn-Cyrl` and basic Mongolian letters U+1820–U+1842 for `mn-Mong`. Punctuation and shaping controls alone cannot satisfy the traditional-script check. Fixture tests run the production checker and reject process-spawn failures explicitly.

Focused verification: `npx vitest run tests/help-script-validation.test.ts tests/help-language.test.ts` from `apps/shell` passed 11 tests in two files. The whole-manual checker correctly exits with 54 missing-edition failures. These checks prove the fallback and mechanical guards, not completed translations.

## Contextual UI drafts added 2026-11-24

The traditional-script preview additionally contains 229 TodOffice-authored contextual drafts for primary Home, ribbon and Settings labels and selected descriptions. These are **not native-speaker reviewed** and are kept separate from the eight source-backed action aliases. Existing sourced terms win on collisions. At the user’s request, specialist labels including Font, Style, Format, Markdown and format initialisms use English-sound display spellings in Mongol bichig. These are explicit authored drafts, not standardized or native-approved transliterations. File extensions, protocol identifiers and executable syntax retain their exact forms.

Fifteen selected single-word spelling records were checked using the [Greg Eck CC0 dictionary lookup snapshot](https://github.com/AltangerelG/react-mongol/blob/371fc5de16d0498d540db19c68b7d2ee0f5265a9/src/generated/eck.ts), which attributes the [pinned original dictionary](https://github.com/suragch/mongolian-datasets/tree/bccea69accbcba06e503cb55d8176f55c56a3d68/eck). Dictionary spellings do not validate phrase grammar, contextual meaning or office terminology. No community translation queue or full dictionary was imported into the app. `packages/i18n/localization-sources/ui-drafts.json` records the selected spellings and is included in distribution notices.

The strict inventory distinguishes 8 source-backed messages and 218 matched drafts from 7,650 remaining literal fallbacks in `mn-Mong`. The catalog has 237 entries; aliases and currently unmatched entries explain why catalog size differs from matched-message count. Two dynamic templates and embedded vendor interfaces still require separate review.
